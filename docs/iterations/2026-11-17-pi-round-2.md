## 2. 未修但不隐瞒的能力边界

- **独立性仍是自述**：`reviewer.context_id != author.context_id` 只能证明「记录不同」，不能证明「真的不同推理路线」。
- **静音阈值（-50 dBFS）只测电平**：440Hz 正弦也能通过；判定「是否中文人声」需要 ASR，本框架不内置。
- **schema 未禁额外字段**：`additionalProperties` 未设置，产物可携带任意扩展字段（本轮 problem.json 就用了 `provenance`/`derived` 记录证据边界，属有意保留）。
- **G4a 静态检查不是沙箱**：`lesson_scene.py` 只能是「可解析」，真实渲染必须在 Docker/MCP 内完成。

## 4. 合并上游 vision-first 政策后的合规影响（必须重做 G0）

`e2ec869..ab1af67` 引入的政策：**图像理解只能由具备原生多模态视觉能力的 Agent 直接观察完成，禁止用 OCR / Python / Pillow / OpenCV / 文字识别 API / 图像转文字脚本代替 Agent 识图**，并且「不能仅把文件路径字符串交给文本模型就假定已经识图」（见 `AGENTS.md`、`prompts/codex/vision-first.md`）。

对本轮 `workspaces/pi-local-001` 的直接影响：

- 本轮 G0 的 `problem.json` 是通过一次**脚本化的多模态模型调用**（base64 内联图片 → 多模态模型 → 文本转写 → 文本 Agent 结构化）得到的。它**不是 OCR**，但按新政策仍属于「脚本式图像转文字管线」，因此：
  - `problem.json` 的视觉证据链在新政策下**不合规**，`check --stage intake` 通过只代表结构与哈希合规；
  - 正确做法是用 `prompts/codex/vision-first.md`：由真正看到图片的 Agent（如 Codex `--image`）亲自观察后写出 `problem.json`，并在回复中先复述亲眼所见内容；
  - 若当前 Agent 无法访问图片，**必须直接声明无法读题并停在 G0**，不得再用脚本代替看图。
- 第 3 节中「改为直接调用 operator 网关的视觉模型完成」这条记录予以保留但不作为可接受的方案，仅作为「为何该 run 的 G0 证据不可信」的证据。
- 门禁层可加固方向（P2）：`check_intake` 增加可机读的 `provenance.vision_source` 声明（`agent_native` / `scripted`），脚本对 `scripted` 给出明确警告而不是静默通过——这样政策才不会只停留在文档。
